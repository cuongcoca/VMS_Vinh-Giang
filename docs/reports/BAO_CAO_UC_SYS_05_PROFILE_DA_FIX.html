Đã xây dựng đầy đủ chức năng xem & sửa Họ tên / Số điện thoại và Đổi mật khẩu ngay trong màn Hồ sơ của cả 3 app di động (thủ kho, xe nâng, kiểm kê). Toàn bộ 17 test case thuộc Ưu tiên 1 (Nhóm 1 + Nhóm 2 trong báo cáo lỗi trước) đã được fix và kiểm thử tự động đạt 18/18. TC20 (tự cắt khoảng trắng tên) cũng được khắc phục luôn trên bản mobile.

2. Nguyên nhân & cách khắc phục

A

Trước khi fix

  • 3 trang Hồ sơ mobile chỉ hiển thị tên + vai trò, không có form sửa Họ tên / SĐT → mọi case cập nhật & validate đều fail.
  • Nút "Đổi mật khẩu" trỏ đường dẫn cứng /wms/system/change-password (thủ kho, kiểm kê) hoặc /auth/change-password không tồn tại (xe nâng). Trên các build standalone mobile (basePath /thukho, /kiemke, /xenang) bấm vào không chuyển màn.
B

Giải pháp

Tạo 1 component dùng chung MobileAccountSettings đặt ngay trong trang Hồ sơ (inline), không điều hướng chéo instance → tránh hoàn toàn lỗi basePath. Component gọi API theo basePath của chính build hiện tại nên mỗi app tự gọi API của mình (cùng 1 cơ sở dữ liệu).
  • Thông tin cá nhân: nút "Chỉnh sửa" → sửa Họ tên + SĐT → "Lưu". Có kiểm tra rỗng, định dạng SĐT (10 số bắt đầu bằng 0), độ dài tên, tự cắt khoảng trắng, và lưu vào localStorage để giữ dữ liệu sau refresh.
  • Đổi mật khẩu: mở form ngay tại chỗ (mật khẩu hiện tại / mới / xác nhận), validate khớp + độ dài, gọi API đổi mật khẩu, thành công thì đăng xuất để đăng nhập lại bằng mật khẩu mới.

File thay đổi:

  • src/components/mobile/MobileAccountSettings.tsx (mới — dùng chung)
  • src/app/thukho/profile/page.tsx, src/app/forklift/profile/page.tsx, src/app/kiemke/profile/page.tsx (gắn component, bỏ link đổi mật khẩu hỏng)

4. Cách kiểm chứng

  • Kiểm thử tự động (Playwright headless): đăng nhập tài khoản thật, chạy lần lượt 18 kịch bản trên component dùng chung (qua app Xe nâng) → 18/18 PASS.
  • Kiểm tra render 3 app: truy cập /thukho/profile, /forklift/profile, /kiemke/profile → đều trả về HTTP 200 và nạp component đúng.
  • Vì cả 3 app dùng cùng 1 component với cùng cách gắn, hành vi đã kiểm chứng áp dụng đồng nhất cho cả 3 vai trò.
Lưu ý môi trường: kiểm thử chạy trên môi trường local (DB local). Để bản QA trên VPS công ty ghi nhận "Pass", cần deploy code lên VPS rồi QA test lại trên app mobile thật.
