Vai trò & phạm vi

Kiểm kê làm việc trên giao diện mobile (/kiemke/*) và một phần trên desktop (tạo phiên). Nhiệm vụ: đếm tồn thực tế theo vị trí hoặc theo mã hàng, hệ thống tự so với 'SL hệ thống' để ra chênh lệch; khi có lệch thì lập phiếu điều chỉnh chuyển cho Quản lý duyệt.

Mỗi chức năng nêu rõ luồng, bàn giao, bảng database đọc/ghi (kèm chuyển trạng thái phiên kiểm kê), và các trường hợp đã kiểm thử. Lưu ý kết nối lỗi: kết quả kiểm kê dẫn tới phiếu điều chỉnh, nhưng bước DUYỆT điều chỉnh (vai trò Quản lý) hiện không cập nhật tồn thực — nên vòng kiểm kê chưa khép kín (xem mục cuối).

2. Tạo phiên kiểm kê (theo vị trí / theo mã hàng) ĐẠT

/wms/stock-count/new

Khởi tạo phiên: chọn kiểu BY_LOCATION (đếm theo ô) hoặc BY_ITEM (đếm theo mã hàng) và chọn các vị trí/mã cần đếm. Hệ thống chốt 'SL hệ thống' (system_qty) cho từng mục từ tồn pallet hiện tại.

🔗 Thuộc / liên quan luồng

  • CP-08. Có thể tạo trên desktop (Kế toán/Kiểm kê) rồi đếm trên mobile.

⚡ Ảnh hưởng

Ghi stocktake_sessions + stocktake_counts. system_qty được 'đóng băng' tại thời điểm tạo phiên để so sánh.

🗄️ Database — ĐỌC (hiển thị từ bảng)

pallet_lines (tính system_qty) locations item_codes pallets

🔁 Chuyển trạng thái

Phiên: OPEN.

✍️ Database — GHI (thay đổi bảng)

  • stocktake_sessions — INSERT code STK-YYYY-NNNN, type BY_LOCATION/BY_ITEM, status=OPEN.
  • stocktake_counts — INSERT mỗi mục: location_id|item_code_id + system_qty = Σ qty_box pallet (IN_STORAGE/IN_STAGING).

🔌 API gọi tới

POST /api/stock-count
GET /api/stock-count/[id]

3. Đếm thực tế & ghi chênh lệch ĐẠT

/kiemke/tasks

Mở phiên, với mỗi mục nhập SL THỰC ĐẾM (kèm lô/HSD thực tế nếu khác). Hệ thống tự tính chênh lệch = thực đếm − hệ thống và chuyển phiên sang COUNTING. Có thể đếm theo lô từng pallet trong ô.

🔗 Thuộc / liên quan luồng

  • CP-08 — khúc giữa. Đếm xong → hoàn tất → nếu lệch thì chuyển đối chiếu.

⚡ Ảnh hưởng

Ghi stocktake_counts (actual_qty, discrepancy, lot_actual, expiry_actual, counted_by/at) + đổi phiên → COUNTING.

🗄️ Database — ĐỌC (hiển thị từ bảng)

stocktake_counts pallet_lines (chi tiết pallet/lô trong ô)

🔁 Chuyển trạng thái

Phiên: OPEN → COUNTING → (complete) RECONCILING | CLOSED.

✍️ Database — GHI (thay đổi bảng)

  • stocktake_counts — UPDATE actual_qty + discrepancy = actual − system_qty + counted_at; lot_actual/expiry_actual nếu nhập.
  • stocktake_sessions — UPDATE OPEN→COUNTING (started_at) khi bắt đầu nhập; complete: → RECONCILING (có lệch) hoặc CLOSED (khớp).

🔌 API gọi tới

PUT /api/stock-count/[id] (batch counts)
POST /api/stock-count/[id]/complete
POST /api/stock-count/[id]/add-unexpected

5. Lập phiếu điều chỉnh từ chênh lệch ⚠️ (vòng chưa khép kín) ĐÃ FIX

/wms/inventory/adjustments/new

Khi phiên có chênh lệch (RECONCILING), tạo phiếu điều chỉnh tồn (type STOCKTAKE_RESOLVE) gắn với phiên — mỗi dòng: mã hàng, SL trước, SL điều chỉnh. Phiếu PENDING chờ Quản lý duyệt.

🔗 Thuộc / liên quan luồng

  • CP-08 — bước cuối. Bàn giao: Kiểm kê LẬP phiếu → Quản lý DUYỆT (→ đáng lẽ cập nhật tồn + đóng phiên).

⚡ Ảnh hưởng

Ghi adjustment_vouchers + adjustment_lines (PENDING). Khi Quản lý duyệt: cập nhật TỒN THỰC (pallet_lines) theo chênh lệch + phiên kiểm kê → CLOSED. Vòng kiểm kê khép kín.

🗄️ Database — ĐỌC (hiển thị từ bảng)

stocktake_counts (chênh lệch) item_codes

🔁 Chuyển trạng thái

adjustment_vouchers: PENDING → (Quản lý) APPROVED; stocktake_sessions: RECONCILING → CLOSED (khi duyệt).

✍️ Database — GHI (thay đổi bảng)

  • adjustment_vouchers — INSERT ADJ-YYYY-NNNN, type=STOCKTAKE_RESOLVE, reason_code=STOCKTAKE, stocktake_session_id, status=PENDING.
  • adjustment_lines — INSERT item_code_id, qty_before=system_qty, qty_adjust=chênh lệch, qty_after.

🔌 API gọi tới

POST /api/adjustments (stocktake_session_id, type=STOCKTAKE_RESOLVE)
GET /api/stock-count/[id]/discrepancy

✅ ĐÃ KHẮC PHỤC & kiểm chứng trên VPS: Vòng kiểm kê nay KHÉP KÍN: sau khi Quản lý duyệt, tồn thực được cập nhật vào pallet_lines (đã kiểm chứng giảm 2 thùng trên VPS).
🔧 Vấn đề (đã sửa): 🛑 Vòng kiểm kê chưa khép kín: phiên + phiếu điều chỉnh được tạo/duyệt đúng quy trình, nhưng bước DUYỆT (POST /api/adjustments/[id]/approve, vai trò Quản lý) chỉ ghi audit + đổi status, KHÔNG cập nhật pallet_lines.qty_box → tồn kho không phản ánh kết quả kiểm kê. Đây là cùng một lỗi nêu ở báo cáo Quản lý (chức năng #12).
Giải pháp đã áp dụng: Sửa API duyệt điều chỉnh để áp SL chênh lệch vào pallet_lines trong cùng transaction. Khi lập phiếu nên chỉ định pallet_line/lô đích để biết cập nhật vào đâu.
