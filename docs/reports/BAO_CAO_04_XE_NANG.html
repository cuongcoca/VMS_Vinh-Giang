Vai trò & phạm vi

Xe nâng làm việc trên giao diện mobile (/xenang/forklift/*), thường quét QR pallet/vị trí. Đây là vai trò 'di chuyển hàng vật lý': nhận pallet đã xác nhận từ Thủ kho rồi xếp vào vị trí, điều chuyển trong kho, rút hàng theo FEFO ra khu chờ xuất (nguyên pallet hoặc một phần — tách pallet con), và hoàn trả pallet (luồng duy nhất được sửa nội dung pallet đã xác nhận, có audit).

Mỗi thao tác đều: kiểm tra ràng buộc (trạng thái pallet, loại/sức chứa/định dạng mã vị trí), cập nhật pallets + locations, ghi một dòng movements và một bản ghi audit_logs.

1. Hàng đợi xe nâng & KPI ĐẠT

/xenang/forklift

Màn hình việc-cần-làm: danh sách pallet CONFIRMED đang chờ xếp vị trí, kèm tổng SL, HSD gần nhất, mã phiếu nhập; KPI số pallet chờ xếp / đang ở khu chờ xuất / số lệnh luân chuyển; cảnh báo lô cận HSD.

🔗 Thuộc / liên quan luồng

2. Xếp pallet vào vị trí (Put-away) ĐẠT

/xenang/forklift/put-away

Quét pallet (CONFIRMED) + quét/nhập mã ô vị trí → đặt pallet vào ô. Hệ thống kiểm tra: định dạng mã (X-NN-NN), ô tồn tại, là ô CHỨA (STORAGE), không bảo trì, còn sức chứa (số pallet & cân nặng). Sau khi xếp: pallet vào kho, ô chuyển USING/FULL.

🔗 Thuộc / liên quan luồng

  • CP-03 (BLOCKER). Bàn giao: Thủ kho XÁC NHẬN pallet → Xe nâng XẾP → hàng có vị trí trong kho.
  • Là điều kiện để tồn kho hiển thị 'khả dụng' (IN_STORAGE).

⚡ Ảnh hưởng

Ghi pallets (IN_STORAGE + location_id), locations (status), movements (PUT_AWAY), audit. Sai vị trí → tồn theo vị trí sai.

🗄️ Database — ĐỌC (hiển thị từ bảng)

pallets locations (+ pallet trong ô để tính sức chứa)

🔁 Chuyển trạng thái

Pallet: CONFIRMED → IN_STORAGE. Ô: EMPTY → USING → FULL.

✍️ Database — GHI (thay đổi bảng)

  • pallets — UPDATE status CONFIRMED→IN_STORAGE, location_id.
  • locations — UPDATE status → USING (hoặc FULL nếu đủ max_pallets).
  • movements — INSERT PUT_AWAY (to_location_id, performed_by).
  • audit_logs — INSERT PUT_AWAY (location_code, cân, số pallet sau).

🔌 API gọi tới

POST /api/forklift/put-away
GET /api/locations/by-code
GET /api/locations/available
GET /api/scan/resolve

3. Chuyển vị trí (Relocate) ĐẠT

/xenang/forklift/relocate

Chuyển pallet IN_STORAGE từ ô hiện tại sang ô khác (gom hàng, tối ưu lối đi). Kiểm tra ô đích hợp lệ + còn sức chứa; cập nhật trạng thái ô nguồn (EMPTY nếu hết) và ô đích.

🔗 Thuộc / liên quan luồng

  • CP — tối ưu sắp xếp kho. Ghi audit RELOCATE.

⚡ Ảnh hưởng

Ghi pallets (location_id), locations (nguồn + đích), movements (RELOCATE), audit.

🗄️ Database — ĐỌC (hiển thị từ bảng)

pallets locations (nguồn + đích + pallet trong ô)

✍️ Database — GHI (thay đổi bảng)

  • pallets — UPDATE location_id (giữ IN_STORAGE).
  • locations — UPDATE ô nguồn → EMPTY/USING, ô đích → USING/FULL.
  • movements — INSERT RELOCATE (from/to_location_id, reason).
  • audit_logs — INSERT RELOCATE (old/new location_code).

🔌 API gọi tới

POST /api/forklift/relocate

4. Rút ra khu chờ xuất theo FEFO (nguyên / một phần) ĐẠT

/xenang/forklift/stage-out

Rút hàng IN_STORAGE ra khu chờ xuất (KCX). Hệ thống GỢI Ý theo FEFO (hạn dùng gần hết xuất trước). Hai chế độ: rút NGUYÊN pallet (FULL) hoặc rút MỘT PHẦN theo dòng (PARTIAL) — khi rút một phần, hệ thống TÁCH tạo pallet con `{mã}-P{n}` cho phần rút, giảm SL/cân pallet cha.

🔗 Thuộc / liên quan luồng

  • CP-04 (BLOCKER) — rút FEFO. Bàn giao tiếp theo: Kế toán làm phiếu xuất / giao hàng từ KCX.
  • FEFO đảm bảo hàng cận date đi trước.

⚡ Ảnh hưởng

Ghi pallets (IN_STORAGE→IN_STAGING hoặc tạo pallet con IN_STAGING), pallet_lines (giảm khi tách), locations (ô nguồn EMPTY, KCX USING), movements (STAGE_OUT), audit.

🗄️ Database — ĐỌC (hiển thị từ bảng)

pallet_lines (IN_STORAGE, sort expiry asc nulls last) pallets locations (OUTBOUND_STAGING)

🔁 Chuyển trạng thái

Pallet: IN_STORAGE → IN_STAGING (hoặc sinh pallet con IN_STAGING).

✍️ Database — GHI (thay đổi bảng)

  • pallets — FULL: UPDATE IN_STORAGE→IN_STAGING + location KCX. PARTIAL: INSERT pallet con (parent_pallet_id, split_seq, code {mã}-P{n}) IN_STAGING; UPDATE cân pallet cha.
  • pallet_lines — PARTIAL: giảm qty_box/qty_unit/weight_kg dòng cha; tạo dòng con cho phần rút.
  • locations — Ô nguồn → EMPTY (khi rút full/cạn); KCX → USING.
  • movements — INSERT STAGE_OUT (mode FULL/PARTIAL, reason_code PALLET_SPLIT khi tách).
  • audit_logs — INSERT STAGE_OUT_FULL / STAGE_OUT_PARTIAL.

🔌 API gọi tới

GET /api/forklift/fefo-suggest?item_code_id=
POST /api/forklift/stage-out (mode=FULL|PARTIAL)

5. Hoàn trả pallet (có sửa nội dung) ★ AUDIT ĐẠT

/xenang/forklift/return

Trả pallet từ khu chờ xuất (IN_STAGING) về một ô lưu kho trống (khách hủy đơn, dừng xuất...). Đây là LUỒNG DUY NHẤT cho phép sửa dòng pallet (SL/lô/HSD) sau khi pallet đã xác nhận — mọi sửa đổi đều ghi audit. Lý do bắt buộc ≥ 5 ký tự.

🔗 Thuộc / liên quan luồng

  • CP-05 (HIGH ⚠️ AUDIT). Bàn giao ngược: từ KCX trả lại kho lưu trữ.

⚡ Ảnh hưởng

Ghi pallets (IN_STAGING→IN_STORAGE + location), pallet_lines (nếu sửa), locations, movements (RETURN), audit (RETURN + EDIT_PALLET_LINE_VIA_RETURN cho từng dòng sửa).

🗄️ Database — ĐỌC (hiển thị từ bảng)

pallets (+lines+item_code) locations (ô đích phải EMPTY)

🔁 Chuyển trạng thái

Pallet: IN_STAGING → IN_STORAGE.

✍️ Database — GHI (thay đổi bảng)

  • pallets — UPDATE IN_STAGING→IN_STORAGE, location_id, total_weight_kg (nếu sửa qty).
  • pallet_lines — UPDATE qty_box/lot/expiry/manufactured_date theo line_updates (recalc weight/qty_unit).
  • locations — Ô nguồn → EMPTY, ô đích → USING.
  • movements — INSERT RETURN (reason).
  • audit_logs — INSERT RETURN + 1 bản EDIT_PALLET_LINE_VIA_RETURN cho mỗi dòng bị sửa (old/new).

🔌 API gọi tới

POST /api/forklift/return (pallet_id, location_id, reason, line_updates[])
