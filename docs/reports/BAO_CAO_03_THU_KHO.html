Vai trò & phạm vi

Thủ kho làm việc trên giao diện mobile (đường dẫn /thukho/*). Đây là vai trò 'tay chân' của luồng nhập: tiếp nhận hàng thực tế, đếm số thực nhận, đóng pallet và xác nhận để bàn giao cho Xe nâng. Thủ kho cũng tạo nhanh mã hàng khi gặp hàng chưa có mã, và lập phiếu nhập tạm khi hàng về đột xuất.

Mỗi chức năng nêu rõ: thuộc luồng nào, nhận bàn giao từ / chuyển cho ai, đọc/ghi bảng nào (kèm chuyển trạng thái phiếu & pallet), và các trường hợp chuẩn + biên đã kiểm thử.

2. Tiếp nhận phiếu nhập & đếm thực nhận ĐẠT

/thukho/inbound

Mở phiếu PENDING do Kế toán gửi → 'Bắt đầu tiếp nhận' (RECEIVING) → nhập SL THỰC NHẬN từng dòng (hệ thống tự tính chênh lệch so với dự kiến) → 'Gửi đối chiếu' (RECONCILING) cho Kế toán.

🔗 Thuộc / liên quan luồng

  • CP-01 — khúc giữa luồng nhập. Bàn giao: Kế toán GỬI phiếu → Thủ kho TIẾP NHẬN+ĐẾM → trả lại Kế toán đối chiếu.

⚡ Ảnh hưởng

Ghi inbound_requests (RECEIVING, received_by) + inbound_lines.qty_received (+ discrepancy_note tự động) + audit. Số thực nhận là dữ liệu gốc cho đối chiếu & chênh lệch.

🗄️ Database — ĐỌC (hiển thị từ bảng)

inbound_requests inbound_lines (+item_code)

🔁 Chuyển trạng thái

Phiếu: PENDING → RECEIVING → RECONCILING.

✍️ Database — GHI (thay đổi bảng)

  • inbound_requests — UPDATE PENDING→RECEIVING (received_at, received_by); rồi RECEIVING→RECONCILING khi gửi đối chiếu.
  • inbound_lines — UPDATE qty_received + discrepancy_note (auto khi lệch dự kiến); ghi chú tay lưu cột note.
  • audit_logs — INSERT START_RECEIVING.

🔌 API gọi tới

POST /api/inbound/[id]/receive
PUT /api/inbound/[id]/lines/[lineId]/receive
POST /api/inbound/[id]/finish-receiving
GET /api/inbound/[id]

3. Lập pallet & xác nhận ĐẠT

/thukho/pallet/new

Đóng hàng thành pallet: tạo pallet từ phiếu nhập (tự sao chép các dòng hàng của phiếu — auto-populate, tính cân & SL lẻ), sửa dòng nếu cần (khi đang đếm), rồi XÁC NHẬN pallet để sẵn sàng cho Xe nâng xếp vị trí.

🔗 Thuộc / liên quan luồng

  • CP-01 → CP-03. Bàn giao: Thủ kho XÁC NHẬN pallet → Xe nâng XẾP vào vị trí.
  • Mã pallet PLYYMMDD.STT sinh race-safe (advisory lock theo ngày).

⚡ Ảnh hưởng

Ghi pallets + pallet_lines + audit. Pallet phải ≥ CONFIRMED thì phiếu nhập mới chốt được và hàng mới vào tồn. Cân pallet (Σ weight) quyết định được xếp vào ô có đủ sức chứa hay không.

🗄️ Database — ĐỌC (hiển thị từ bảng)

pallets pallet_lines inbound_requests inbound_lines item_codes

🔁 Chuyển trạng thái

Pallet: EMPTY/COUNTING → CONFIRMED → (Xe nâng) IN_STORAGE.

✍️ Database — GHI (thay đổi bảng)

  • pallets — INSERT code PLYYMMDD.STT, status=COUNTING (có dòng) / EMPTY (rỗng), total_lines, total_weight_kg; UPDATE → CONFIRMED (confirmed_by) khi xác nhận.
  • pallet_lines — INSERT (sao từ inbound_lines: qty_box=qty_expected, qty_unit=qty_box×units_per_box, weight_kg=qty×weight/thùng); PATCH sửa dòng khi COUNTING.
  • audit_logs — INSERT CREATE_PALLET, CONFIRM_PALLET.

🔌 API gọi tới

POST /api/pallets (auto_populate_lines)
POST /api/pallets/[id]/confirm
PATCH /api/pallets/[id]/lines/[lineId]
POST /api/pallets/[id]/unlock
GET /api/pallets/[id]
GET /api/pallets/next-code

4. Tạo nhanh mã hàng ĐẠT

/thukho/item-code/new

Khi gặp hàng chưa có mã chuẩn, Thủ kho tạo nhanh 'mã hàng tạm': chỉ cần tên rút gọn + ĐVT (+ số lẻ/thùng, cân). Nếu không nhập mã, hệ thống tự sinh mã TEMP-... Mã này ở trạng thái pending, chờ Kế toán chuẩn hóa.

🔗 Thuộc / liên quan luồng

  • CP-01/02 phụ trợ. Bàn giao: Thủ kho TẠO NHANH (pending) → Kế toán CHUẨN HÓA (standardized).

⚡ Ảnh hưởng

Ghi item_codes (pending). Mã này dùng được ngay trong dòng pallet/phiếu, sau đó Kế toán hoàn thiện.

🗄️ Database — ĐỌC (hiển thị từ bảng)

item_codes

🔁 Chuyển trạng thái

item_codes.status: pending (→ Kế toán: standardized).

✍️ Database — GHI (thay đổi bảng)

  • item_codes — INSERT short_name, unit_id, units_per_box, weight_per_box; code = TEMP-<timestamp>-<rand> nếu để trống; status='pending'.

🔌 API gọi tới

POST /api/item-codes
GET /api/item-codes/by-code
GET /api/item-codes/by-barcode

5. Nhập đột xuất (phiếu tạm PNT) ĐẠT

/thukho/adhoc/new

Khi hàng về mà chưa có phiếu yêu cầu nhập (về sớm, NCC mới, hàng trả lại...), Thủ kho lập 'phiếu nhập tạm': chọn nguồn hàng, người giao, lý do, ảnh chứng từ, thêm dòng hàng. Phiếu PENDING chờ Kế toán chuẩn hóa.

🔗 Thuộc / liên quan luồng

  • CP-02 — nhập hàng đột xuất. Bàn giao: Thủ kho LẬP phiếu tạm → Kế toán CHUẨN HÓA → PHN chính thức.

⚡ Ảnh hưởng

Ghi inbound_temps + inbound_temp_lines (PENDING). Bắt buộc nguồn hàng + người giao + lý do (validate server).

🗄️ Database — ĐỌC (hiển thị từ bảng)

inbound_temps inbound_temp_lines suppliers item_codes

🔁 Chuyển trạng thái

inbound_temps: PENDING (→ Kế toán: STANDARDIZED).

✍️ Database — GHI (thay đổi bảng)

  • inbound_temps — INSERT code PNT-YYYY-SSSS, source_type, delivered_by, reason, photo_urls, status=PENDING.
  • inbound_temp_lines — INSERT item_code_id, qty_box, lot, expiry_date.

🔌 API gọi tới

POST /api/inbound-temp
POST /api/inbound-temp/[id]/lines
DELETE /api/inbound-temp/[id]/lines
GET /api/inbound-temp/next-code
